# 实验报告

## 一．项目背景及意义

在高校教育体系中，学科竞赛是培养学生创新能力、实践能力和团队协作精神的重要载体。然而，当前高校学生在组队参赛过程中面临显著的"找人难"问题：一方面，学生的技能信息分散在各个社交平台，缺乏结构化的展示渠道；另一方面，传统的人工匹配方式依赖熟人推荐或群聊发布，效率低下且难以精准评估候选队友的实际技能水平。

南昌大学竞赛队友匹配平台正是针对这一痛点而设计开发的全栈 Web 应用系统。平台以"技能标签"为核心数据结构，允许用户自主标注个人技能及其熟练程度（了解/掌握/精通），并结合竞赛类别、招募人数等维度，实现了从"发布招募"到"智能推荐"再到"申请审核"的完整组队闭环。

项目的核心创新在于引入了基于加权标签交集的匹配算法：系统自动计算每位平台用户与招募需求之间的技能匹配度百分比，并将 Top 5 推荐给招募发布者，显著提升了组队效率。平台采用 Spring Boot + Vue 3 的现代全栈技术架构，集成了 JWT 无状态认证、Redis 缓存优化、MyBatis Plus 数据持久化以及基于角色的权限控制（RBAC），具备良好的用户体验和可扩展性。

本项目具有双重意义：从实用角度，它为高校学生提供了一站式的竞赛组队解决方案，降低了信息不对称带来的组队成本；从教学角度，它完整覆盖了《信息管理概论/Java Web 应用开发》课程的核心知识点，包括数据库设计、RESTful API 开发、前端工程化、安全认证、缓存策略以及 UML 建模，是一个典型的课程综合实训案例。

## 二．研究现状

目前高校竞赛组队主要依赖以下几种传统方式：

**社群与论坛模式：** 学生通过 QQ 群、微信群、贴吧等渠道发布组队信息。这种方式门槛低但信息碎片化严重，招募帖子很快被新消息淹没，缺乏有效的搜索和筛选机制。发布者需要反复顶帖，而寻找队伍的学生也难以全面对比不同招募需求。

**通用竞赛平台：** 部分高校或第三方平台（如赛氪、大学生竞赛网）提供了竞赛信息发布功能，但其组队模块通常仅支持简单的留言或报名，缺乏对参与者技能的结构化评估和自动匹配能力。

**校内管理系统：** 极少数高校开发了内部的竞赛管理系统，但功能主要集中在竞赛报名和成绩管理层面，组队环节仍依赖人工协调。

**技术层面的不足：** 上述方案普遍存在"重信息发布、轻智能匹配"的问题。它们缺少以技能标签为粒度的用户画像构建，也没有基于标签交集的自动推荐算法。此外，大多数非商业性平台在安全认证、缓存优化、角色权限等方面存在短板。

本平台在以下方面做了针对性改进：引入多级技能标签体系（了解/掌握/精通）实现用户能力的细粒度量化；设计加权匹配算法自动计算技能契合度；采用 JWT + Spring Security 实现无状态安全认证；利用 Redis 缓存推荐结果以应对高并发场景；通过 RBAC 角色控制区分普通用户与管理员的权限边界。这些设计使平台在功能完整性和技术规范性上较现有方案有明显提升。

## 三．项目流程与技术路线

### 3.1 项目开发流程

项目采用瀑布式与迭代式相结合的开发方法，分为五个阶段：

**需求分析阶段：** 明确平台目标用户（南昌大学在校学生），梳理核心功能需求（注册登录、技能标签管理、招募发布与搜索、智能匹配推荐、申请审核、队友管理、管理后台），确定技术选型（Java 17 + Spring Boot 3.0 后端，Vue 3 + Element Plus 前端）。

**系统设计阶段：** 设计数据库 E-R 模型，确定 7 张核心数据表（用户表、标签表、用户标签关联表、竞赛类别表、招募信息表、招募所需标签表、申请表）及其关系；绘制用例图（10 个核心用例）、类图（分层架构）、包图及部署图；设计 RESTful API 接口规范（统一 Result 响应封装）。

**编码实现阶段：** 后端先行搭建 Spring Boot 项目骨架、配置 Spring Security + JWT 认证链、MyBatis Plus 数据访问层；实现 7 个 Service 类（含匹配推荐核心算法）和 6 个 Controller 类；前端基于 Vite + Vue 3 Composition API 构建 SPA 应用，编写 7 个视图页面、1 个导航组件和 6 个 API 模块。

**测试阶段：** 使用 12 个测试账号（含 1 个管理员）和 11 条招募数据进行功能验证；测试普通用户/管理员的权限隔离（403 拦截）；验证 Redis 缓存的读写与失效逻辑；验证匹配推荐算法对不同用户产生差异化结果。

**部署阶段：** 后端打包为 Spring Boot 可执行 JAR 并部署于本机 8080 端口；前端使用 Vite 开发服务器部署于 3000 端口，通过 Vite 代理转发 `/api` 请求至后端。

### 3.2 技术架构

**后端技术栈：** Spring Boot 3.0.12（应用框架，内嵌 Tomcat）→ Spring Web MVC（RESTful API）→ MyBatis Plus 3.5.5（ORM，LambdaQueryWrapper 类型安全查询）→ MySQL 8.0（关系型数据库）。横切关注点包括：Spring Security 6 + JWT（jjwt 0.12.3）实现无状态认证与角色鉴权；Redis 6.0+（Lettuce 客户端）缓存标签列表和推荐结果；BCryptPasswordEncoder 加密用户密码。

**前端技术栈：** Vue 3.4（Composition API + `<script setup>` 语法）→ Vue Router 4.3（Hash 路由 + 导航守卫）→ Element Plus 2.5（UI 组件库）→ Axios 1.6（HTTP 客户端，拦截器自动注入 JWT Token、统一处理 401/403 错误）→ Vite 5.0（构建工具，ESM 开发服务器）。

**核心算法 — 基于技能标签交集的加权匹配评分：** 对于每一条招募需求，系统获取其所需标签集合 T_req；遍历平台所有其他用户，对每位用户计算其个人标签集合 T_user 与 T_req 的交集；累加交集中每个标签的熟练度分数（了解=1、掌握=2、精通=3），得到用户总得分 S；匹配度 = S / (|T_req| × 3) × 100%；按匹配度降序返回 Top 5。系统同时实现了该算法的逆向版本——为用户推荐匹配度最高的招募，应用于首页"推荐给我的招募"模块。

**数据库设计核心要点：** user 表新增 role 字段（VARCHAR(20)，值 USER/ADMIN）实现角色区分；user_tag 表通过 proficiency 字段（TINYINT，1-3）记录熟练度等级，为匹配算法提供量化基础；application 表通过 status 字段（PENDING/ACCEPTED/REJECTED）跟踪申请全生命周期；recruitment 表通过 status 字段（OPEN/CLOSED）控制招募可见性与可操作性。7 张表通过外键字段（user_id、tag_id、recruitment_id 等）建立关联，覆盖用户、技能、招募、申请四大业务域。

### 3.3 功能模块

系统包含五大功能模块：**用户模块**（注册、登录、个人信息维护、技能标签增删）、**招募模块**（发布、搜索、分类筛选、关闭、申请加入）、**匹配推荐模块**（候选队友推荐、招募推荐、Redis 缓存）、**队友管理模块**（申请审核、队友关系建立、联系方式可见）、**管理模块**（竞赛类别管理、用户管理、招募管理、权限隔离）。

## 四．总结

在本次实验中，我负责了系统的整体架构设计与核心功能开发。后端方面，完成了 Spring Boot 项目搭建、Spring Security + JWT 认证链配置、7 个 Service 的实现（含基于标签交集的加权匹配推荐算法），以及 6 个 Controller 共 20 余个 RESTful API 端点的开发，并实现了基于角色的权限控制（RBAC）。前端方面，基于 Vue 3 Composition API 开发了 7 个页面（首页、登录、注册、招募广场、招募详情、个人中心、管理后台），实现了路由守卫、Axios 拦截器以及基于 Element Plus 的响应式 UI。此外，还完成了 Redis 缓存策略的设计与实现、12 个测试账号与 15 条申请记录的测试数据构建。通过本实验，深入掌握了 Spring Boot + Vue 3 全栈开发流程，理解了 JWT 认证机制、RBAC 权限模型、缓存优化策略以及推荐算法的工程实现。
